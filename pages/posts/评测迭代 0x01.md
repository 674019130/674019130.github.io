学习「评测迭代」的笔记。整体路径是：从生产 trace 出发，经粗筛 + 精筛两层过滤，再到 prompt / 模型两条优化路线的闭环。

```text
生产 trace
    │
    ├── 粗筛层（便宜、自动、覆盖广）
    │     ├─ LLM-as-Judge 抽样打分    ← 主观质量
    │     ├─ 用户点踩                  ← 显式负反馈
    │     └─ 停留时长 / 复制率 / 重问率 ← 隐式行为信号
    │
    ├── 精筛层（贵、人工、高质量）
    │     └─ 标注师挑 hard case → 评测集 + 训练集
    │
    └── 优化层（两条路并行）
          ├─ Prompt 层：自进化 + 蒙特卡洛搜 fewshot
          └─ 模型层：SFT（学会做对） / DPO（学会偏好）
```

主要学习内容：

- 抽样 Trace
- LLM as a Judge
- 蒙特卡洛优化 / 蒙特卡洛搜索树
- SFT 和 DPO 的区别

## 抽样 Trace

1. agent 的 Trace 普遍更大更「胖」，数据存储成本被放大
2. Trace 的结构趋于标准化
3. 采样决策点从 head 迁移到 tail，必须做 tail sampling 或更复杂的 trace-aware sampling。因为关键判据在 trace 末尾：**是否需要保留这条 trace，往往取决于最终的 evaluation/guardrail 结果、总 token 数、是否进入 retry loop ——这些只有 trace 跑完才知道。**
4. 哪些数据需要进行采样？
   1. 错误 Trace
   2. 慢 Trace（latency > p99）
   3. cost 异常
   4. guardrail / eval 不通过
   5. successful trace：probabilistic 5–10%
   6. 高频 (agent name, route) 组合做 dynamic sampling，保证每个组合都有最小样本数
   7. 按 token 数/费用加权。比如 1M token 的 trace 即使是 success 也要关注，它代表了一个潜在失控的 trajectory。
   8. https://github.com/honeycombio/refinery，一个可以动态调整采样频率的开源代理
5. dynamic sampling——按某个 key 组合的频率自动调整采样率。工程意义：常见组合 (agent_name, model, tool_name) 高频时少采，低频组合（往往是新出的 trajectory）多采，自动平衡"**高频路径噪声**"和"**长尾路径稀缺**"。这是给 agent 这种 **高基数 trace** 量身定做的。
6. 线上跑 **LLM-as-a-judge** 或 guardrail，不通过的 trace 100% 保留并送进 annotation queue。
7. 被采保留的 trace 必须能 deterministic replay 出来，所以要保留：完整 prompts、模型版本、temperature/seed、tool schema 版本

## LLM as a Judge

1. 评分协议 4 个维度
   1. **评分粒度**
      1. 绝对打分 e.g. 1-5 likert（1-5 Likert 就是把评分压缩到 5 个离散等级，每个等级对应一个语义标签。非常不同意、同意、中立、不同意、非常不同意）
      2. pairwise e.g. A/B 进行比较
      3. Listwise e.g. 多输出比较
   2. **是否需要参考答案**
      1. 有 gold answer
      2. 仅靠 judge 自身知识和 rubric
   3. **Judge 的实现**
      1. prompted
      2. fine-tuned
   4. **评分内容**
      1. 单一总分
      2. 多维度打分

2. OpenReview 的 Pairwise or Pointwise? (2025) 给出一个反直觉结论：pairwise 翻转率约 35%，pointwise 翻转率仅 9%——pairwise 更直观但偏差更显著；这与早期"pairwise 天然更可靠"的观点形成对冲。

3. 偏差清单（bias）
   1. Position bias 位置偏爱，在做 pairwise 的时候偏爱 A / B 的位置
   2. verbosity（啰嗦） / length bias 长度偏爱，更偏爱较长的输出
   3. Self-preference / self-enhancement bias 自我偏爱，偏爱自己更熟悉（低困惑度）的文本
   4. Preference leakage (Li et al., ICLR 2026, arXiv:2502.01534)：当训练数据生成器与评测 judge 同源（同模型/同家族/有继承关系），即使不是"自评"，也存在系统性偏倚，影响比 self-preference 更隐蔽、对 leaderboard 排名影响更大。
   5. **以下 4 种**偏差都源于 LLM 是基于表面文本模式做判断，而非真正理解内容。它们和 verbosity bias（更长 → 更高分）属于同一类——形式信号被错当成质量信号。
      1. Sentiment bias（情感倾向偏差），对积极乐观礼貌的倾向于高分，消极批判冷淡的倾向于低分
      2. Authority bias（权威性偏差），被「权威信号」误导（假装引用论文 / 学术腔 / 技术黑话 / 拉丁词）
      3. Fallacy oversight bias（逻辑谬误盲视偏差），检查不出回答中的逻辑谬误，只要阅读流畅、结构完整、看似在论证，就倾向于给高分
      4. Concreteness bias（具体性偏差），偏爱更有细节/更有数字数据的回答

      解决方案：

      - 用结构化 rubric 强制 judge 分维度评分（事实性、逻辑性、风格分开）
      - 在 prompt 里显式告诫"忽略表面权威性，验证引用真实性"
      - 对关键事实用外部 verifier（检索、单测、计算器）兜底，而不是让 judge 自己判断
      - 使用思考模型会受到更小的影响

   6. 有一些专门被训练来做 judge 的模型，Prometheus / Prometheus 2 等，也有专门的 reasoning 模块，外挂在 judge 上，提高准确率和一致性

### 降本与提质的工程手段

1. 多个小型异构 judge 投票代替单一高质量模型，cost 降低至 1/7，与人一致性更高
2. 构建 agent 环境，把 judge 当做 tool，同样可以降低成本，提高与人一致性
3. 多 agent 辩论也比单 judge 效果更强

---

### 评分协议与 Debias 最新进展

1. 把 Likert 打分换成 Boolean QA checklist，相关性显著超 G-Eval。
2. <u>每次 judge 调用限制 3–5 个维度，避免"一锅烩"稀释关注度。</u>
3. 多模态 judge 在 pairwise 上表现还可以，但在 scoring / ranking 上系统性偏差更严重。更好的做法是纯文字 LLM + 图像描述，效果往往不输端到端 MLLM judge
4. Debias 技术最新进展
   - <u>Both-orderings averaging（Wang et al., 2024）：**调用两次 judge 交换 A/B 位置取均值或要求双向一致**；已成生产标配。</u>
   - Length-aware rubric：<u>**在 prompt 显式约束"忽略长度"或对长度做 normalization**</u>。
   - Cross-family judging：<u>**避免用同家族 judge 评同家族输出**</u>（应对 preference leakage）。
   - Confidence calibration：<u>**Trust or Escalate (ICLR 2025) 提出选择性评测——只有 judge 信心高时才用其结论，低信心 escalate 给人类**</u>。
   - Statistical reporting：How to Correctly Report LLM-as-a-Judge Evaluations (2025, arXiv:2511.21140) 提出 bias-corrected estimator + 严格置信区间。

### 何时不该用 LLM-as-Judge

社区的明确共识：

1. 有可验证答案的任务（数学、单测、SQL 是否跑通、JSON schema）——用规则/单测/exact match 更便宜更可靠。
2. <u>**高风险决策**</u>（医疗诊断、法律判定、内容审核终审）——judge 无问责性，必须人审。
3. <u>**强领域知识**</u>（专科医学、专业法律、底层系统编程）——通用 LLM 缺少领域 ground truth，会产生看似合理实则错误的"superficial evaluation"。
4. <u>**训练 / 评测 同源闭环**</u>——会触发 preference leakage 与 reward hacking 的复合风险。
5. 需要长期纵向比较（跨模型版本的排行榜）——judge 自身在升级，时间维度上分数不可比。

## 蒙特卡洛优化 / 蒙特卡洛搜索树

这块东西突然开始接触的话有点洼地，不建议突然深究。只要知道：

- 蒙特卡洛优化：在连续/参数空间里靠随机采样找最优解，没有"路径"概念。
- MCTS：在离散决策树里靠随机采样选下一步，每一步都是一个分叉。

它们是同一思想（用随机采样替代精确计算）在两种问题结构上的不同形态。就行了。

### 蒙特卡洛优化 (Monte Carlo Optimization)

问题形式：找 $\theta^* = \arg\max_\theta f(\theta)$，但 $f$ 不可导、贵、或没有解析形式（典型如：仿真器、黑盒环境、整段策略的 return）。

核心思路：在 $\theta$ 上**随机采样**，靠 reward 反馈不断把采样分布推向高 reward 区域。

几个代表性方法（从简单到精巧）：

**(a) 随机搜索 / 随机重启**

均匀采样 $\theta$，留 reward 最高的。

**(b) 模拟退火 (Simulated Annealing)**

当前点附近扰动一个 $\theta'$，按 Metropolis 准则接受：

$$P(\text{accept}) = \min\left(1, e^{(f(\theta') - f(\theta))/T}\right)$$

温度 $T$ 慢慢降到 0，从"广撒网"过渡到"精修"。

直观点：

**模拟金属退火的物理过程**——把金属加热到高温让原子自由运动，然后缓慢冷却，原子就能排列到能量最低的晶格结构。如果冷却太快（淬火），原子会被困在缺陷态，得不到最优结构。算法里也是同样的道理。

**贪心算法**：每步只往脚下更低的方向走 → 滚到最近的坑里就停了。

<u>**模拟退火**：刚开始你身上绑着弹跳鞋（高温），能蹦得很高，跳过任何小山丘；随着时间推移弹跳鞋慢慢失效（降温），最后只能踏踏实实往下走 → 大概率能找到真正的最低谷。</u>

**(c) <u>交叉熵方法 (CEM, Cross-Entropy Method) — 最值得记的一个</u>**

什么是交叉熵：用 -log 对你做的事件发生的概率预测进行惩罚。

- 用分布 p(θ; μ, σ) 采 N 个样本
- 跑出 reward，取 top-k 精英 (elite set)
- 用精英重新 fit 分布 (更新 μ, σ)
- 回到 1，分布越来越窄、越来越准

是个"分布在 reward landscape 上做梯度上升"的直观替代品。MuZero 之前的 PlaNet、PETS 这些 model-based RL 都在用 CEM 做规划。

> 蒙特卡洛优化的所有方法，本质都是在回答"我手上只有 $f(\theta)$ 的样本，怎么把 $\theta$ 推向高分区"。

## SFT 和 DPO

数据格式：

```text
SFT:  (prompt, response)
DPO:  (prompt, chosen, rejected)   ← 每条样本都是一对
```

SFT 只需要"对的答案"，DPO 必须有对比对。这是为什么标注 DPO 数据贵——你得对同一个 prompt 给出两条回复并排序。

---

**SFT (Supervised Fine-Tuning, 监督微调)**

在预训练模型的基础上，用人工标注的高质量「输入-输出」对来继续训练模型。比如给模型看大量「问题 → 理想回答」的样本，让它学会模仿这种回答风格。这是让基础模型变得「会聊天、会听指令」的第一步，**本质上就是普通的监督学习**。

**<u>对于输入 A，应该输出 B。</u>给出标准答案，照着学。**

**DPO (Direct Preference Optimization, 直接偏好优化)**

用来对齐人类偏好的方法，通常在 SFT 之后做。训练数据是「偏好对」：同一个问题，有一个「更好的回答」(chosen) 和一个「更差的回答」(rejected)，让模型学会提高好回答的概率、降低差回答的概率。

DPO 是作为 RLHF (基于人类反馈的强化学习) 的替代方案出现的。RLHF 需要先训练一个奖励模型，再用 PPO 之类的强化学习算法去优化，流程复杂、调参麻烦。

> DPO 的巧妙之处在于，它通过数学推导把「奖励模型 + RL」这套流程合并成了一个直接的分类损失函数，直接在偏好数据上做监督学习就行，不需要单独的奖励模型，也不需要 RL 那套采样过程。

**<u>对于输入 A，B 比 C 更好。提高 B 相对于参考模型的概率，同时降低 C 相对于参考模型的概率。</u>**
